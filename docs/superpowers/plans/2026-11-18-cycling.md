# Cycling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Bike mode beside Transit: speed-scalable ride-time bands from one precomputed grid, and click-for-ride
showing the street path, distance and an elevation profile.

**Architecture:** A new `bike` pipeline stage queries the existing MOTIS server (BIKE `one-to-many` for every cell,
one direct `plan` per ~500 m block), samples SRTM heights along the paths, and writes `bike.grid.bin` +
`bike.routes.json`. The web app converts the bike grid into the existing `Grid` shape at the chosen speed, so
contours, bands and the map are reused; a separate ride hook, panel and overlay handle clicks in Bike mode.

**Tech Stack:** Python 3.12 (numpy, pandas, shapely, geopandas, requests; pytest), MOTIS 2.11.4 HTTP API,
React 19 + react-leaflet + Vite + Tailwind (vitest, Testing Library), Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-11-18-cycling-design.md`

## Global Constraints

- Static site only; bike assets fetched only when Bike is first selected (`bike.grid.bin`) / first clicked (`bike.routes.json`).
- Speeds exactly `12 · 15 · 20 · 25` km/h, default 15, subtitle `leisurely · commuter · fit · e-bike`.
- Grid file: gzip of `"PMB1"`, `u16` version 1, `u32` width, `u32` height (little-endian), then `seconds: u16` plane (`0xFFFF` unreachable), then `path: u16` plane (`0xFFFF` none). Row 0 = south. Not named `.gz` (same reason as transit grids).
- Seconds are at `refSpeedKmh`; distance = `seconds × refSpeedKmh / 3.6` m; minutes at speed v = `round(seconds × refSpeedKmh / v / 60)`, clamped to 254, sentinel → 255.
- Routes file: `{refSpeedKmh, shapes, lengths, elev, paths}` exactly as spec §2 (amended: `lengths`, nullable `elev`/ascent/descent).
- `street_routing_max_direct_seconds: 10800`; bike queries use `max`/`maxDirectTime` 10800.
- Blocks `--bike-block 5` cells; elevation samples every 50 m; DEM median filter 5×5; ascent hysteresis 2 m; mismatch tolerance 120 s, warn > 5 %.
- Bike colour `#16a34a` as `MODE_COLORS.BIKE`.
- Copy: "Ride {m} min · {km} km at {v} km/h" (km to 1 dp), "↑ {a} m  ↓ {d} m", "Outside the mapped area", "No bike route within 3 h", "Route details unavailable", "Bike time to Perth CBD", "Couldn't load bike data".
- `index.json.bike` absent → Bike toggle hidden; transit behaviour unchanged.

## Review Focus

1. Click on an unreachable cell (verge, park) inside a reachable block → snaps to the nearest reachable cell within 2 cells, like transit, not "No bike route". Test in Task 6.
2. Rapid speed or mode switching while the bike grid loads → only the latest view's bands and status are shown. Test in Task 7.
3. Old `public/data/index.json` without `bike` → no Bike toggle, and nothing bike-related is fetched. Test in Task 8.
4. A route open in Transit, then switching to Bike (and back) → the panel re-resolves the same point in the new mode. Asserted in Task 10's e2e.
5. Path samples on an SRTM tile seam (lat −32.0 / lon 116.0) → continuous heights, no void or jump. Test in Task 2.

### Task 4: Segment table with elevation

**Files:**
- Modify: `data_gen/bike.py`
- Test: `data_gen/tests/test_bike_segments.py`

**Interfaces:**
- Consumes: `elevation.Dem`, `sample_positions`, `along`, `interpolate_water`, `climb`; `pipeline.decode_polyline` (step polylines are precision 6), `pipeline.encode_polyline`, `pipeline.to_metres`; `RouteTables.SIMPLIFY_DEG` value (0.00005).
- Produces: `class SegmentTable` with:
  - `__init__(self, dem: Dem | None, is_wet: Callable[[np.ndarray, np.ndarray], np.ndarray])` (`is_wet(lat, lon) → bool array`).
  - `add_path(self, start_cell: int, leg: dict) -> list` → `[seconds, metres, ascent, descent, [segment ids]]` from a MOTIS leg (`duration`, `distance`, `steps[*].polyline.points`, `steps[*].toOsmNode`). Any NaN in a new segment's heights, or `dem is None` → that segment's `elev` is `None`. Path ascent/descent from the concatenated profile using stored heights; `None` if any segment's `elev` is `None`.
